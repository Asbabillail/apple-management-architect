# Practical advisory release — 8 November 2026

The existing private EDU-MDM Architect was saved as v0.3.0, preserving its identity and private audience. Its 37 text files matched the reviewed candidate; the original binary icon was retained. It now has thirteen skills. The general source is [published here](../advisory/edu-mdm/README.md); this is not a public installable plugin package.

## Useful scope

ASM, Jamf School, managed iPads and AppleCare for Enterprise advisory work: explain tasks in ordinary language, teach one useful step at a time, provide concise expert procedures, distinguish credentials and products, and document evidence without borrowing another customer's configuration.

The new approved-app self-service guidance separates required from optional apps, installation from usage controls, account controls from licensing, and schedule intentions from device-delivery evidence. Recovery guidance states the limits of offline commands and locked/restarted connectivity. No command, deployment, credential operation or live integration was performed.

## Response evidence

Twenty distinct synthetic requests generated 25 actual response texts. A separate assistant-context review found four mandatory omissions; revised guidance produced four passing isolated retests. The latest answer for each of the twenty cases meets this bounded review. The full suite was not rerun on the final snapshot. Exact model identity/settings were unavailable. This is not an external human review, installed-host routing check, hardware test, general accuracy score or evidence of real time savings. ## Next: demonstrate operational value

First inspect whether Jamf School Student is present and usable, then verify applicable licenses, assignment, installation and exception handling. Record support visits, administrator minutes and failed installs over comparable periods, including setup and maintenance effort. Test scheduled restrictions and recovery separately; do not infer them from catalog success.

Only expand read-only integrations after a repeatable workflow is demonstrated. Write operations and automatic execution need explicit targets, authorization, audit records, failure handling and recovery validation.
